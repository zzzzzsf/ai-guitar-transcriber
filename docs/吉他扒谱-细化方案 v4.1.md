## 1. D 组:分发与质量

### 1.1 分轨 sidecar 分发(v4.0 第 3 节"高配分轨外部引擎"细化)

**二进制来源(不自编译,用社区产物)**:
- 高配档:`demucs.cpp`(github.com/sevagh/demucs.cpp)官方 Release。更新慢、Apple Silicon 可能缺产物 → 用 GitHub Actions 自己交叉编译补缺,挂到自己 Release。
- 均衡档(INT8 量化):demucs.cpp 不直接支持 INT8,走 **ONNX 版 demucs 模型 + onnxruntime C++ CLI**。把 PyTorch demucs 转 ONNX,配 onnxruntime C API。
- 统一封装 `separator-cli` 子进程,对外只暴露 `input.wav → output_stems/*.wav`,与主程序解耦。
- **模型选择**(对照 demucs v4 README):高配档用 `htdemucs_6s`(**6 源,直接分出 guitar 轨**,这是吉他扒谱的关键;README 提示 piano 轨效果差但不影响吉他);若追求更高 SDR 可选 `htdemucs_ft`(fine-tuned,SDR 9.0dB,但 4 源不出 guitar 轨,需二次处理)。均衡档 INT8 量化基于 `htdemucs_6s`。**已核实(2026-10)**:demucs.cpp 官方 README 确认以 GGML 权重格式支持 `htdemucs / htdemucs_6s / htdemucs_ft / hdemucs_mmi` 全系 v4 模型,htdemucs_6s 可用性前提成立。

**分发策略(按需下载,不打进安装包)**:
- 双源:**HuggingFace(主)+ 国内镜像(自建 OSS 或 Gitee Releases)**,设置里可切镜像。
- **SHA-256 校验** + HTTP Range 断点续传 + 进度条。
- 缓存目录:`~/.ai-guitar-transcriber/models/<version>/`,版本号独立,支持模型升级。

**打包集成**:
- 不走 Tauri `bundle.externalBin`(那是打进安装包的)。运行时从用户目录 spawn。
  - Tauri:`tauri::api::command::new_command` 或 Rust `std::process::Command`
  - Electron:`child_process.spawn`
- 二进制名按 `target_triple` 后缀区分平台(`separator-cli-x86_64-pc-windows-msvc.exe` / `-aarch64-apple-darwin`)。

**运行时依赖陷阱**:
- demucs.cpp 依赖 onnxruntime 动态库(`onnxruntime.dll/.so/.dylib`)+ Windows VC++ Redistributable。
- 下载包必须把 onnxruntime 一起打包成 zip;Windows 首启检测 VC++ 运行时缺失 → 提示安装。

**许可证**:demucs.cpp = MIT,onnxruntime = MIT。写进 `THIRD-PARTY-NOTICES.txt`,sidecar 目录保留各自 NOTICE。另两项 v4.0 §6 合规表未覆盖、待补记:alphaTab 内置合成器的 GM soundfont 许可、测试数据集(GuitarSet/EGDB)许可——Step 3/4 接入时核验并写入 NOTICES(2026-10 审查补记)。

### 1.2 测试基准与准确率指标(v4.0 缺失项)

**测试集(三类样本,各 20~30 条)**:
- (a) 干净吉他独奏(指弹)、(b) 弹唱(人声+吉他)、(c) 乐队混音(吉他被掩盖)、(d) 长曲 ≥10 分钟 1~2 条(验证轻量档分段转写,见 §3.2)
- 来源:公开数据集 GuitarSet / EGDB、自录、YouTube CC 协议片段
- **GuitarSet 自带弦品级 GT**(六弦拾音器标注)——免人工标注直接测"弦品准确率"特有指标;其为拾音器干声,属 (a) 类,不覆盖 (b)(c)(后者属 Step 4 分轨验证范畴)。**语料建设是变速接线/基线校准/泛音验证等多项的共同前置,应列为第 0 项主动建设,而非被动等待**(2026-10 计划审查)
- Ground Truth:Guitar Pro / TuxGuitar 人工扒谱导出 `.gp5` / `.mid`;和弦标注人工写一份

**指标定义**:
- **音符级 F1**:onset 容差 ±50ms + pitch 精确匹配 → Precision / Recall / F1
- **弦品准确率**:pitch 正确的音符里,(弦+品)与 GT 一致的比例 —— 吉他谱特有指标
- **和弦标注 F1**:小节级和弦 label 的 F1
- **BPM 误差**:|检测 - GT|,统计倍频/半频错误率
- **时值准确率**:音符时值(几分音符)匹配率

**回归测试**:CI 跑固定 5 条独奏样本,每次改算法输出对比报告,防 Viterbi 权重调退化。

**基线目标(首期,初步估计,需 basic-pitch 实测后校准)**:独奏音符 F1 > 0.85、弦品准确率 > 0.75;弹唱/混音 F1 > 0.65(受分轨质量制约)。注:basic-pitch README 未公布具体 F1,论文数字因数据集差异大,本基线为工程目标而非 SOTA 对照,Step 3 实测后据实调整。

**外部对照基线(2026-10 新增)**:MuScriptor(103M/307M 档,Kyutai 开源多乐器转写,见 §5)在同一测试集跑分,作外部参照线而非竞速目标——校准本项目定位:**护城河在指法层(弦品准确率/可弹性)而非音高检测**。商业参照 Klangio(Guitar2Tabs/Transcription Studio,云端订阅,免费档仅前 20~30 秒):其用户高频抱怨"全部音符挤在一根弦上",恰是指法层缺陷的反例,印证 Viterbi 寻路的价值。

**多乐器测试样本(随 Profile 扩展同步补)**:每个新 Profile 上线时补该乐器样本(§2.3);可复用公开集:琵琶 = PipaSet/TEAS(IEEE Access 2022,首个琵琶转写多模态数据集)、鼓 = STAR Drums(TISMIR 2025)。

**工具**:离线评测用 `mir_eval`(Python 标准 MIR 库);纯 TS 算法(Viterbi/Capo/扫弦聚拢)用 Vitest 单测,输入 MIDI 数组 → 断言输出 alphaTex。

### 1.3 BYOK 大模型 API 安全与降级(v4.0 第 4.2 节细化)

**Key 存储(绝不用 localStorage;具体方案随 §5 打包外壳决定)**:
- Tauri:`tauri-plugin-stronghold` 或 OS keychain 绑定
- Electron:`keytar`(Windows Credential Manager / macOS Keychain / Linux Secret Service)
- 移动端:Capacitor SecureStorage / Tauri Mobile 安全存储插件
- 注:外壳未定前,这层先按"主进程代理 + OS keychain"抽象设计;Step 4 装外壳时再选具体库。

**请求方式(主进程代理,不能前端直 fetch)**:
- 前端只发 `{ provider, prompt, model }` 给主进程;主进程从 keychain 取 Key、注入请求头、发 fetch、返回结果。**Key 永不进入 webview 内存**。
- Tauri:Rust `reqwest` 或 `tauri-plugin-http`;Electron:主进程 Node `fetch`。
- 附带好处:绕过浏览器 CORS。

**降级策略(网络/Key 失败时仍可用)**:
- 和弦标注 → 降级为本地音程规则推断(小节内音高集合匹配常用和弦字典)
- "AI 改谱"(降把位)→ 降级为本地规则(高品位同音移到低品位)
- 双吉他拆轨 → 无降级,直接禁用按钮并提示

**输出前置校验(2026-10 审查补)**:LLM 返回的 alphaTex 先过**可解析校验**(alphaTab 试解析,失败即拒收)+ **diff 预览**(增删改高亮),用户确认后才落谱——防劣质/异常输出破坏整谱;snapshot 回滚(§2.2)是兜底,不是第一道防线。

**多 provider 适配**:`llmClient.ts` 统一抽象成 `chat(messages, opts) → stream`。DeepSeek/Kimi/OpenAI 兼容 OpenAI 格式走同一分支;Gemini 走原生格式分支。

**隐私提示**:首次填 Key 时弹窗明示"你的谱面 alphaTex 文本将发送到你所选模型提供商,请确认认可其隐私政策"。

### 1.4 Step 4 执行规格(2026-10 补;§1.1/1.3/2.2/3.4 的运行时编排与工作分解)

v4.0 对 Step 4 只有一句话("档位切换 + demucs 对接 + 大模型 API"),本节补齐可执行规格。**前置顺序**(呼应 §6 执行序 ⑤⑥):Step 3 真实语料校准通过 → 外壳 spike 拍板 → 下文工作分解。

**三档运行时编排(TierRouter + separatorRunner 契约)**:

```text
TierRouter(用户选档)
├── 轻量档: decode → 带通(§3.2) → basic-pitch → Profile 流水线(不分轨)
├── 均衡档: 首次触发下载模型(§1.1 双源+SHA256+续传)
│          → separator-cli spawn(INT8 htdemucs_6s,3s 窗口) → stems/
│          → 取 guitar.wav → 走轻量档后半段
└── 高配档: 同上,FP16 htdemucs_6s + GPU(10s 高重叠窗)
```

```ts
// 主进程命令,前端只调用不接触进程
runSeparation(input: string, opts: {
  tier: 'balanced' | 'high';
  onProgress: (pct: number) => void;   // 解析子进程 stdout
  signal: AbortSignal;                 // cancel
  timeoutMs: number;
}): Promise<{ stems: Record<'guitar'|'bass'|'drums'|'vocals'|'piano'|'other', string> }>;
```

- **失败降级链**:spawn 失败/超时/崩溃 → **自动回落轻量档**(原曲直接转,UI 一次性提示,不中断出谱);模型下载失败 → 引导切换镜像源后重试,不自动回落。

- **stems 缓存**:按源音频内容 hash 缓存于工程 `stems/`(§2.2 引用模式),切换档位重跑不重复分轨;hash 未变且档位相同直接复用。
- **通用化**:separatorRunner 抽象为通用 sidecar runner——MuScriptor(§5)未来接入复用同一管道与降级框架。

## 2. C 组:插件接口与存储(采用更优方案)

### 2.1 IInstrumentProfile 契约 — 函数式可组合 pipeline

**设计理由(为何弃 OOP 继承)**:
- abstract class + Template Method 把 hook 顺序硬编码在基类,鼓这种乐器要 override `routeFretboard` 为 no-op —— 这是"反继承"信号,说明 pipeline 步骤不是所有乐器共用同一条直线。
- 函数式 pipeline(借鉴 `@magenta/music`):每个 transform 是纯函数,可任意组合、顺序可调、好测、AI 生成命中率高。

**类型定义(冻结;2026-10 修订:`InstrumentConfig` 补 `perStringMaxFret`,`instrument` 联合类型随二期乐器清单扩展或放开为 string+注册表校验,其余不变)**:

```ts
// Basic Pitch 原始输出
type RawNote = {
  onset: number;        // 秒
  duration: number;    // 秒
  pitch: number;       // MIDI 0-127
  velocity: number;    // 0-127
  pitchBend: { time: number; cents: number }[];
};

// 来自 quantizer(见 3.1)
type BeatSection = { start: number; end: number; bpm: number; timeSignature: [number, number] };
type BeatGrid = { sections: BeatSection[]; beats: number[] };

type InstrumentConfig = {
  tuning?: number[];            // 调弦(空弦 MIDI 数组,按弦序;不要求单调——尤克里里 G4C4E4A4 等非单调定弦天然兼容,候选按"每弦独立算品"生成)
  capo?: number;
  stringCount?: number;
  perStringMaxFret?: number[];  // 每弦最大可按品(班卓第 5 弦短弦仅约 5 品可按;缺省 = 到指板末端)
};

type FrettedNote = {
  string: number; fret: number;
  onset: number; duration: number; pitch: number;
  bend?: { time: number; cents: number }[];
  techniques?: ('bend' | 'slide' | 'hammer' | 'pull' | 'palmMute')[];
};

type TranscriptionResult = {
  alphaTex: string;
  notes: FrettedNote[];
  meta: { tuning: number[]; capo: number; suggestedCapo?: CapoSuggestion[] };
};

type CapoSuggestion = { capo: number; tuning: number[]; score: number; reason: string };

// 统一 transform 签名
type Transform<I, O> = (input: I, ctx: ProfileContext) => O;

interface IInstrumentProfile {
  instrument: 'guitar' | 'bass' | 'piano' | 'drums' | 'vocal';
  pipeline: Transform<RawNote[], TranscriptionResult>[];  // 显式声明,顺序自定义
  defaultConfig: InstrumentConfig;                        // zod 运行时校验
  serializeForLlm(result: TranscriptionResult): string;   // → alphaTex 文本(BYOK 用)
}
```

**Pipeline hook(可组合的通用步骤,每个 Profile 选自己需要的子集)**:
- `filterNotes(RawNote[]) → RawNote[]`(音域/复音/碎音/**泛音误检抑制**,见下注)
- `clusterEvents(RawNote[]) → RawNote[]`(扫弦聚拢 + 推弦合并 + **推弦漏检修复 bendrescue**)
- `detectTuning(RawNote[], InstrumentConfig) → TuningResult`(调弦+Capo 推导)
- `routeFretboard(RawNote[], TuningResult) → FrettedNote[]`(Viterbi 寻路,鼓/人声不含)
- `detectArticulation(FrettedNote[], BeatGrid) → FrettedNote[]`(**hammer-on/pull-off/slide/palmMute 等演奏技巧检测**,基于已分配弦品;闷音 PM 也在此标注)
- `toAlphaTex(FrettedNote[], BeatGrid) → string`(格式化,含技巧标签)

> articulation 在 routeFretboard 之后,因为 hammer/pull/slide 判定需要"同弦相邻品"等已分配的弦品信息;闷音(palmMute)则基于音色特征(短促 + 低频衰减),可在 filterNotes 阶段预标记、此处确认。

> **泛音误检抑制(2026-10 补;必须在 routing 之前)**:多音高检测的经典错误是八度/谐波混淆——被误检为独立音符的泛音多落在基频 **+19 半音(3 次泛音,12·log₂3≈19.02)与 +24 半音(4 次泛音)** 区间(合成演示音频上表现为 19~24 品伪音符;真实录音同样存在此类误检,仅分布不同,不可等语料才做)。抑制规则:同簇内相对更强低音 +19/+24 半音、能量显著更弱、onset 对齐 → **标记"疑似泛音"而非直接删**,交 §2.4 编辑器处置;另配合 basic-pitch 阈值收紧(onset/frame sensitivity)。**认知澄清:Viterbi 不能抑制伪音符**——音符既已检出,音高必须落在某处,`w_fret`/`w_pos_prior` 只能在有替代位置时偏好低把位;且 `reach` 约束的是簇内跨度(最高品−最低品),不约束绝对品位,孤立高把位单音 stretch=0 不受惩罚。实现位置:规则需要"同簇/onset 邻接"信息,放 clusterEvents(聚拢后簇内判定)或 filterNotes 内自做轻量 onset 邻接分组皆可,首期建议前者(复用聚拢结果)。

**注册机制**:`ProfileRegistry` 按 `instrument` 字符串 lookup。首期只注册 Guitar。ES module 动态 import 懒加载(切到该乐器时按需加载,减小首屏体积)。**远期才考虑第三方插件沙箱**,首期所有 Profile 都是项目内置 TS。

**位置**:`src/profiles/IInstrumentProfile.ts`(接口)+ `BaseInstrumentProfile.ts`(抽象基类,文档目录里没有,建议补)+ `GuitarProfile.ts`(首期,覆盖全部 6 个 hook)。

| 钢琴 | ✅ **多谱表大谱表** | PianoProfile 三期(左右手切分点) | ✅ |

**四点结论**:

1. **渲染层全覆盖** —— 人声简谱、钢琴大谱表、鼓谱 alphaTab 都原生支持(v4.0 担心需自研的渲染其实是现成的),插件化承诺在渲染层有完整背书。

4. **音色层 GM 覆盖大部分**,唯人声偏弱(见 §5 留白)。

**扩展乐器五组评估(2026-10 调研定稿;判断框架 = 每件乐器过三道关卡)**

- **关卡①音高转写**(basic-pitch):论文标题即 *A Lightweight Instrument-Agnostic Model for Polyphonic Note Transcription*(arXiv 2203.09893),Slakh 式合成多乐器数据训练,乐器无关——唯一失败类是无音高打击乐(鼓)。
- **关卡②分轨**(htdemucs_6s):仅 6 种 stem(drums/bass/other/vocals/piano/guitar)。**这是扩展乐器最大的现实约束**:尤克里里/小提琴/萨克斯/民乐在混音中全部落在 `other` 轨,与键盘/弦乐群混在一起,无专属 stem → 扩展乐器主打**独奏/干净录音场景**(扒谱典型场景恰是扒独奏段);终局解法 = 乐器感知转写引擎 MuScriptor(§5),一步替换①+②层。
- **关卡③指法**(Viterbi):只需"弦+品"离散结构存在,代价函数换参数即可。

### 2.4 谱面编辑器与人工修正保留(2026-10 审查补 P0 缺口)

**编辑能力(alphaTab 是渲染器不是编辑器;走"改 Score 模型 → 局部重渲染"路径)**:

- 小节级:插/删小节、改拍号/调号
- 实现要点:编辑动作同时写回内部 `FrettedNote[]`——**单一事实源在数据模型,渲染只是视图**

**人工修正 × 自动重算的合并(round-trip,核心机制)**:
- **修正打标**:用户手动改动写入独立的 `editOverlay`(JSON:noteId + 字段 + 值 + 时间戳),**不改写原始转写结果**;工程目录中与 `transcript/` 平级
- **重算触发**(改 BPM/权重档/Capo/调弦/重新检测):流水线重跑出新基线 → `editOverlay` 回放合并——noteId 仍存在则应用字段覆盖;noteId 消失(音符被合并/删除)则丢弃并列入**冲突清单**供确认
- **diff 预览**:合并结果增删改高亮,一键接受或逐条处理(复用 §3.5 变速 diff 预览交互)
- **全局 undo/redo**:编辑动作栈(~100 步上限),与 AI snapshot 分两层——undo 管细粒度编辑,snapshot 管整版回滚

**位置**:`src/persistence/editOverlay.ts`(打标与合并)+ TabViewer 编辑交互 + 属性面板组件。

## 3. B 组:节拍检测与音频前处理

### 3.1 BPM 检测(借鉴 Malody,修订 v4.0 quantizer.ts)

**调研依据**:本地 Malody 4.3.7 是 C++ 编译版(malody.exe + BASS/FMOD/ffmpeg),源码读不到;但同生态的 LumaChartStudio 谱面编辑器(开源)完整实现了 Malody 范式的 BPM 检测。Malody `.mc` 谱面格式确认 BPM 是 **per-section 数组** `time[i].bpm`,原生支持变速曲。

**Malody 生态三大范式(借鉴)**:
1. **谐波相关(HarmonicCorrelation)** 替纯自相关:`corr(lag×0.5)×0.2 + corr(lag)×1.0 + corr(lag×2)×0.15`,同一拍点同时评估半拍/一拍/两拍,直接消歧倍频/半频,不靠先验。
2. **分段 BPM**:支持变速曲(指弹 rubato、摇滚变拍),输出 `BeatSection[]` 而非单一 BPM。
3. **手动 tap 测量**:中位数+离群剔除+圆周相位+置信度。

**自动检测(修订后主算法)**:
1. 低通滤波(截止 ~250Hz,提取节奏低频成分)
2. 能量包络(滑窗 RMS)
3. HFC(High Frequency Content)onset 检测(频谱加权,对瞬态敏感)
4. onset 包络 → **窗口化谐波相关** 求每段 BPM
5. 加权中位数平滑分段,剔除短孤岛段
6. 变速边界精炼 + 对齐 1/16 网格

**交叉验证**:用 basic-pitch 输出的 onset 概率数组作第二路估计;两者偏差 > 10% 时 UI 提示"检测到 BPM 128,存在疑点,确认或手动输入"。(注:onset 概率数组在 basic-pitch TS 高层 API 的暴露程度待 Step 3 验证;拿不到则降级为用 note onset 时间戳序列做第二路估计——2026-10 审查补记)

**手动 tap 测量模式**(借鉴 ManualTempoTapAnalyzer):
- UI:播放音频时按空格/点击 N 次(≥4),实时显示已 tap 数与当前估算 BPM
- 间隔过滤 100ms~2000ms
- 中位数离群剔除:tolerance = max(55ms, median×35%)
- BPM = 60000 / 剩余间隔均值,范围 30~400
- **圆周相位**(atan2 向量和)求 beat 0 落点
- **置信度**:样本置信度 `(taps-3)/9` 先 clamp 到 0.15~1.0,再乘 `(1 - instability×0.75)`,最终 clamp 到 0.05~0.99
- 测完显示"BPM 128,置信度 0.87",置信度 < 0.6 标红

**直接输入 BPM + 风险警告**(用户已知场景):
- 数字输入框 + tap 测量两种入口并存
- **触发警告**:用户输入值与自动检测值偏差 > 5% 时弹警告
- **警告内容**:
  > "你输入的 BPM = 132,与自动检测的 128 偏差 3.1%。
  > 错误的 BPM 会导致:**① 整曲节拍网格错位;② 谱面音符时值(几分音符)失真;③ Viterbi 弦品寻路在错误节拍点对齐,指法可能跟着错**。
  > 仅当你确信原曲 BPM 就是此值(如来自官方谱面资料)时才覆盖。"
- **按钮**:[使用 132 并跳过本次会话警告] / [保留自动检测 128] / [取消]
- **后果级联标记**:确认覆盖后谱面右上角持续显示橙色"BPM: 132(手动)"标记,悬停提示"手动覆盖值,谱面节奏异常请先检查此处"

**拍号检测**:首期默认 4/4;用强拍/弱拍能量分布启发式判断 3/4 / 6/8,但**最终拍号让用户在 UI 下拉改**(4/4、3/4、6/8、2/4),不强行猜。

**量化网格对齐(对照 GP8 补漏:加三连音双网格)**:
- **逐拍双网格检测**:每拍同时评估二等分网格(1/8、1/16、1/32)与三等分网格(三连音),取 onset 拟合误差小者;三等分胜出时输出 tuplet——吉他三连音极常见,只对齐 2 的幂网格会把三连音时值全错记
- 二等分胜出:把 onset/duration 对齐到最近 1/16 或 1/32 网格点
- 容差:距最近网格 > 1/32 时值 → 标"自由节奏"(不量化,保留原时值,常见于 rubato/慢板指弹)
- **量化强度滑块**:严格(全对齐)/ 软(只对齐明显拍点)/ 关(不量化)

**输出**:`BeatGrid = { sections: BeatSection[]; beats: number[] }`

**位置**:`src/core/quantizer.ts`,纯 TS,无外部依赖。

### 3.2 音频前处理(audioPreprocessor.ts)

**输入处理流水线**:
1. **解码**:`OfflineAudioContext.decodeAudioData` 把 mp3/m4a/flac/wav → AudioBuffer(stereo + 原采样率)
2. **stereo → mono**:左右平均 `(L+R)/2`;若检测到相位反相,用 mid-side `(L-R)/2` 兜底
3. **不自做预重采样(2026-10 修正)**:原方案"OfflineAudioContext 预降到 22050Hz,内部用 lanczos"两处站不住——① Web Audio 规范不规定重采样算法,浏览器实现质量不受控(无任何引擎承诺 lanczos);② basic-pitch 内部本就会用自己的配套重采样器降到 22050Hz(官方 README 明确,该数字仅作背景知识保留),预重采样只省一次重复计算,却引入质量不受控环节。**修正:原采样率 mono 直喂 basic-pitch,重采样交给它自己**;若 Step 3 实测其内部重采样有性能问题,再自写纯 TS polyphase 重采样(约 50 行)替代
4. **轻量档带通滤波**(仅轻量档,标准/高配档交给分轨引擎):
   - 串联两个 BiquadFilter:高通 + 低通
   - **下限 70Hz**(吉他最低 E2=82Hz、Drop D D2=73Hz,70Hz 安全保留;滤底鼓/嗡嗡声/DC)
   - **上限 8kHz**(保留吉他泛音到第 6 倍音 ~5kHz,8kHz 留余量;滤镲片高频串音)
5. **音量归一化**(可选):peak normalize 到 -3dB,防动态范围太小
6. **输出**:`Float32Array`(原采样率 mono)给 basic-pitch

**参数权衡**:
- 采样率:重采样交 basic-pitch 内部处理(目标 22050Hz);上游喂任意采样率都会被其归一,自做预重采样无收益且质量不受控(见流水线第 3 步修正)
- 带通 70Hz~8kHz:吉他泛音到第 6 倍音约 5kHz,8kHz 留余量

**性能**:以 3 分钟歌为基准(44.1kHz mono Float32Array 约 32MB,无压力);**长曲(≥10 分钟)分段策略(2026-10 细化)**:轻量档按 60~90 秒分段喂入 basic-pitch(防内存与波形渲染开销随时长线性膨胀;均衡档已有 3 秒窗口切片,§1.1)。分段的设计点在**边界处理**:① 切点优先选检测到的静音/低能量区(避免切断持续音;成功则无需重叠,且 ≥0.4s 静音间隔与 `move_free_gap` 天然对齐);② 固定切点兜底时加 2~5 秒重叠,同音高、时间重叠的音符在重叠区合并去重;③ **分段只作用于 basic-pitch 神经推理——扫弦聚拢/推弦合并/Viterbi/量化一律在合并后的全局 note 流上跑**(note 数据量远小于音频;若按段跑,段首丢失把位上下文,边界指法断裂)。BPM 检测(§3.1 走低通能量包络,非神经)可全曲跑,不受分段影响。由测试集 (d) 类样本(§1.2)验证。

**位置**:`src/core/audioPreprocessor.ts`,纯 Web Audio API,零外部依赖。

### 3.3 五线谱输出细化(对照 Guitar Pro 8;v4.0/v4.1 原疏漏补全)

**背景**:v4.0 只说"Tab + 五线谱",五线谱从未细化。对照 GP8 能力清单与 alphaTex 语法定义(alphaTab develop 分支 `packages/alphatex/src/metadata/bar/` 下 26 个 bar 级元命令),确认**渲染引擎完全支持**(`\ks` 调号、`\clef` 谱号、accidentals、ottava、voiceMode、jump、section、beamingRule、ts、tempo),疏漏在**流水线未生成这些数据**。

**七项补漏(按优先级;标注对已实现代码的影响)**:

1. **调号生成(最高优先,必做)**:KeyFit 调性检测(Krumhansl-Schmuckler)从"Auto-Capo 可选项"升级为**流水线必做步骤**(§4.2 的 `w_keyfit` 作为 Auto-Capo 评分项仍可为 0,两者独立):检测结果写入每段 `BeatSection`,toAlphaTex 生成 `\ks`(语法 `\ks Aminor | \ks Dmajor | \ks C#`)。用户可在 UI 下拉手动改(15 个大小调)。不做此项,C 大调外的曲子五线谱全靠临时记号,谱面不可读。**代码影响:新增 `src/core/keyDetector.ts` + `toAlphaTex` 补 `\ks` 输出**。
2. **三连音/连音量化(§3.1 已同步修订)**:量化改为逐拍双网格检测(二等分 vs 三等分)。**代码影响:现有 `quantizer.ts` 的量化函数补三等分分支 + tuplet 输出**。
3. **休止符生成**:量化后音符间空隙 → 对应时值休止符插入(alphaTex `r` 语法);多声部时各声部独立补休止(二期)。**代码影响:`toAlphaTex` 补休止符填充**。
4. **连音线(Tie)跨小节处理**:音符跨小节 → 拆为两音 + tie 连接;同音高相邻音符判断 tie vs 重复弹奏(按 onset 间隔与 velocity 变化)。**代码影响:量化/格式化补跨小节拆分**。
5. **吉他移调八度确认(Step 3 实测)**:吉他是移调乐器(记谱比实际发音高八度,高音谱号下加 8)。实测 alphaTab guitar staff 默认 clef/ottava 行为,确认五线谱记谱与 MIDI 播放/导出音高一致;不一致则 toAlphaTex 显式输出 `\clef` + ottava。
6. **多声部分配(指弹,二期)**:指弹常 2 声部(旋律符干朝上 + 低音符干朝下),alphaTex voiceMode 支持。首期单声部 + 和弦簇;二期加 `splitVoices` transform(按音高域/时值稳定度分声部)。
7. **反复记号首期不做(明确留白)**:扒谱按实际音频**线性展开**(不猜反复结构),alphaTex jump/section 能力留作后续用户手动添加。

**实现位置**:调号 → `src/core/keyDetector.ts`(新增,必做)+ `toAlphaTex`;三连音/休止符/tie → `src/core/quantizer.ts` + `toAlphaTex` transform(对现有代码为补丁);声部 → 二期 `GuitarProfile.ts` 加 `splitVoices`。

### 3.5 变速曲处理(§3.1 分段 BPM 的增强;两轮分析定稿)

**三种"变速"必须分清**(从音频反推时混在一起,处理策略完全不同):

| 类型 | 性质 | 处理 |
| :--- | :--- | :--- |
| 真变速 | 作曲意图,段落级、持续、不回归(intro 90 → 主歌 120) | 检出分段,谱面标 `\tempo` |
| Rubato | 谱面恒定,演奏者伸缩,**均值回归**(古典/指弹) | **不建段**:单段主 BPM + 软量化容差 |
| 演奏不稳 | 随机抖动,无结构(鼓手 ±3%) | 忽略(段内 CI 宽自动降灵敏度) |

不区分的后果:rubato 当真变速 → 谱面每两小节一个 BPM 标记没法看;真变速当 rubato 抹平 → 段落网格整体错位。

**自动检测三层升级(替代固定阈值;解决小幅变速如 118→122 漏检)**:

1. **统计显著性判据(替代 ±8% 经验阈值)**:每段 BPM 估计自带 95% 置信区间(拍点间隔方差 + 谐波相关峰强度),**段间 CI 不重叠 → 候选真变速**。稳拍下 118→122(仅 3.4%)可检出(间隔差 16ms,CI 半宽约 3.6ms);不稳段 CI 宽自动钝感。注:CI 不重叠是**保守判据**(比 t-test 少检出),牺牲部分灵敏度换低误报——漏检由下方手动入口低成本兜底,与"检测不必完美"的 UX 取舍自洽。
2. **BOCPD 变点检测**:在逐拍 BPM 序列上跑 Bayesian Online Changepoint Detection(纯 TS 约 150 行,无新依赖),输出每时间点的变速后验概率,小而持续的变化可浮出。**渐变识别**:BOCPD 假设段内突变,渐变表现为**密集变点簇**,后处理合并为线性渐变段(逐小节 `\tempo` 插值 + `hide` 中间标记,相邻小节差 <2 BPM 合并);短渐变(≤2 小节)近似为边界突变。
3. **音乐先验加权**:变速点大概率在段落边界(能量 + 音色自相似矩阵的简单结构分割),变点概率在边界处加权;BPM 值 snap 到附近整数/常见值(120/128/140…)。纯吉他独奏结构信号弱时该先验自动退权重。

**候选置信度统一定义**:置信度 = BOCPD 后验概率 × CI 分离度(归一化),驱动渐进 UX。

**手动入口五类(按介入成本升序;首期只做 1 + 5 + 网格 overlay)**:

| # | 入口 | 交互 | 首期 |
| :--- | :--- | :--- | :--- |
| 1 | 一键插段 | 小节标尺点击 → 输入 BPM | ✅ |
| 2 | Tap 测新段 | 播放到变速处 tap N 次(复用 §3.1 tap 测量器,结果落新段而非全曲) | 后续 |
| 3 | 变速表编辑器 | 列表式编辑 + **整表粘贴**(社区变速信息直接贴);校验时间单调、BPM 30~400 | 后续 |
| 4 | tempo map 导入 | **自写轻量 SMF tempo 事件解析**(约 50 行,不依赖 alphaTab 的 MIDI 谱面导入)读用户手头 MIDI 的变速表;GP 文件可直接经 alphaTab Guitar Pro 导入 | 后续 |
| 5 | 检测候选确认流 | 自动检测产出候选点列表(带置信度),逐条确认/拒绝/微调,像 code review | ✅ |

**微调与验证工具**:
- **网格 overlay**:波形上叠加当前 BPM 网格线——网格线是否踩在拍点上,变速对错**一眼可辨**,比听辨快,是最直观的验证方式
- 段 BPM ±0.5 步进微调、分段点在小节线上拖拽、单段循环试听、每段独立 undo
- 改动触发量化 + Viterbi **局部重算**,重算前后时值 diff 预览

**渐进 UX(置信度驱动介入成本)**:
- 高置信度 → 自动应用,不打扰
- 中置信度 → 提示"此处可能有变速(118→122,置信度 0.62),确认?"
- 低置信度/小幅 → 不打扰,但变速表可见,用户 5 秒可加一个点(点位置+输数值,或 tap)

**检测器不必完美,因为修正成本足够低**——对 Malody 生态"人工辅助工具同样完整"观察(§3.1 调研)的正面回应;首期走"自动 + 确认"混合模式,不承诺全自动完美分段。强检测必须配确认工作流,两者设计上绑死。

**真实音频接线(2026-10 计划审查)**:现有验证基于演示轨(干净 BPM 阶梯),真实音频是 BOCPD/CI 判据的**首次实战**——渐变与演奏抖动叠加、段边界模糊是常态,CI 在真实鼓手不稳(±3% 抖动)下自动变钝,漏检率将首次拿到实测。**验收标准**:波形网格 overlay 与拍点目视对齐 + 候选列表查准率——overlay 已实现,接线必须带上,否则用户无法肉眼判断候选对错。

**参数汇总(修订版,替代最初 ±8%/4 小节草案)**:

| 项 | 值 |
| :--- | :--- |
| 真变速判定 | 段间 BPM 95% CI 不重叠,持续 ≥2 小节(最小段) |
| 忽略 | 无固定百分比;段内 CI 宽(演奏不稳)自动降灵敏度 |
| 渐变段 | BOCPD 密集变点簇 → 后处理合并线性段,逐小节 `\tempo` + `hide`(相邻差 <2 BPM 合并);≤2 小节短渐变近似突变 |
| 变速点对齐 | 小节线 + 段落边界先验加权 |
| 边界音符归属 | 变速点对齐小节线;跨界音符按 onset 距离归网 |
| 手动改段 | 同 §3.1 BPM 手动输入警告(错段 = 整段网格错位),确认后全链路重算 |

**BYOK 约束**:`\tempo` 标记写入 guitarPrompts 的 System Prompt 约束——LLM 改谱必须保留 tempo 标记,不得删改分段。

## 4. B 组:Viterbi 弦品寻路与 Auto-Capo

### 4.1 Viterbi 代价函数与权重(v4.0 第 4.1 节第 4 步细化)

**状态空间**:
- 单音候选 `(string, fret)` 通常 ≤ 6 个(经音域约束)
- 和弦簇状态 = 笛卡尔积,但**同弦互斥硬约束**剪枝后实际 ≤ 几百
- 用 **beam search**(每步保留 top-K,K=50~200)防爆炸

**代价函数(借鉴 rayBastard/tabforge 的 tune_viterbi.py,补 4 项代价 + reach 可调)**:
```
TotalCost = w_samestring·C_samestring                          // 硬约束
          + w_stretch·C_stretch(reach)                          // 跨度,reach 可调
          + w_move·C_move(time_factor_k, move_free_gap)        // 把位移动,时间衰减+休止豁免
          + w_string_change·C_string_change                      // 换弦(独立于把位)
          + w_fret·C_fret                                        // 品位绝对
          + w_open·C_open                                        // 空弦偏好
          + w_pos_prior·C_pos_prior(center)                      // V 形低把位先验
```

**各项公式**:

1. **C_samestring(硬约束)**:簇内两音同弦 → `+∞`(实际 `1e9`),用于剪枝。

2. **C_stretch(reach 可调)**:
   - 簇内非空弦音符的 `max_fret - min_fret = stretch`(空弦 0 品不计入)
   - `stretch ≤ reach`(舒适区)→ `C = 0`
   - `stretch > reach` → `C = exp((stretch - reach) · 0.7)`(指数增长)
   - `reach` 默认 4,三档可调(省力档 5 放宽、忠于原音档 3 收紧)

3. **C_move(把位移动,时间衰减 + 休止豁免)**:
   - 把位 = 簇内非空弦品位的平均值(手掌中心);`Δt` = 相邻簇时间间隔
   - `C = |pos_curr - pos_prev| · exp(-Δt · time_factor_k)`(相邻越近惩罚越重,有间隔则衰减)
   - 当 `Δt > move_free_gap` 时 `C = 0`(休止符间隔足够长,手可自由重定位不计惩罚——真实演奏常识)

4. **C_string_change(换弦,独立项)**:`string_curr != string_prev ? 1 : 0`(换弦与换把位是两维度,拆开分别调权)

5. **C_fret(品位绝对)**:`C = fret / 24`(归一化到 0~1,偏好低品)

6. **C_open(空弦偏好)**:`fret == 0 ? -0.3 : 0`(负代价=奖励)

7. **C_pos_prior(V 形低把位先验)**:`C = |fret - center|`,`center` 默认 5(中低把位)。tabforge 经验注释"75% 错误集中在低把位",V 形先验把指法拉回低把位。

**初始权重表(需配合 1.2 测试集调参)**:

| 项 | 权重/值 | 含义 |
| :--- | :--- | :--- |
| `w_samestring` | ∞ | 硬约束 |
| `w_stretch` | 1.0 | 跨度超 reach 指数增长 |
| `w_move` | 0.5 | 把位跳跃(时间衰减) |
| `w_string_change` | 0.3 | 换弦惩罚 |
| `w_fret` | 0.2 | 偏好低品 |
| `w_open` | -0.3 | 轻微鼓励空弦 |
| `w_pos_prior` | 0.4 | V 形低把位先验 |
| `time_factor_k` | 0.5 | 把位惩罚时间衰减陡峭度 |
| `move_free_gap` | 0.4s | 休止间隔>此值免费重定位 |
| `reach` | 4 | 单手跨度舒适阈值(可调) |
| `pos_prior_center` | 5 | V 形先验中心(中低把位) |

**指法风格三档滑块**(UI 暴露,映射权重预设;`w_samestring` 恒为 ∞):

| 档位 | w_open | w_stretch | w_move | w_string_change | w_fret | w_pos_prior | reach | 适用 |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| 省力档(新手) | -0.8 | 1.5 | 0.5 | 0.4 | 0.3 | 0.6 | 5 | 大鼓励空弦、放宽跨度、强低把位偏好 |

**实现位置**:`GuitarProfile.ts` 的 `routeFretboard` transform。权重常量集中 `src/profiles/costWeights.ts`,方便 CI 回归调参对比。

### 4.2 Auto-Capo 评分函数(v4.0 第 4.1 节第 3 步细化)

**候选空间**:
- 调弦:标准(EADGBE)、Drop D(DADGBE),可选 DADGAD / Open G / Open D(用户在 UI 勾选)
- Capo:0~7 品(8 档)
- 总候选 ≈ 调弦数 × 8,标准 + Drop D = 16 种;加特殊调弦 ≈ 30 种

**评分函数(分数越高越优)**:
```
Score(config) = w_openhit · OpenHitRate(config)        // 空弦命中率 0~1
              - w_stretch · AvgStretch(config)         // 平均手指跨度
              - w_fretavg · AvgFret(config)            // 平均品位
              - w_highfret · HighFretRate(config)      // 高品(>12)音符比例
              + w_keyfit · KeyFit(config)              // 曲调契合度(可选)
```

**各项含义**:
1. **OpenHitRate**:经 config.capo 平移后,能在某弦 0 品直接命中的音符占所有音比例
2. **AvgStretch**:给定 config 下跑一次简化版 Viterbi(只取 stretch 项),算各簇平均跨度
3. **AvgFret / HighFretRate**:平均品位、>12 品比例
4. **KeyFit**(评分项可选,调性检测本身必做):曲调与 config + Capo 开放调性契合度。Krumhansl-Schmuckler 调性检测因 §3.3 五线谱调号(`\ks`)需求升级为流水线必做(检测结果双用于调号输出与 Auto-Capo 评分);`w_keyfit` 作为 Auto-Capo 评分项首期仍可为 0

**权重表**:

| 项 | 权重 | 含义 |
| :--- | :--- | :--- |
| `w_openhit` | 2.0 | 空弦命中是首要信号 |
| `w_stretch` | 1.0 | 平均跨度 |
| `w_fretavg` | 0.5 | 平均品位 |
| `w_highfret` | 1.0 | 高品惩罚 |
| `w_keyfit` | 0(首期) | 调性契合,可后置 |

**输出**:返回 **Top 3 候选** config 排序,UI 显示推荐理由(如"Capo 5 + 标准调弦:空弦命中 78%,平均跨度 2.3 品,无 >12 品音")。用户一键采纳或手动改下拉框,前端毫秒级重算。

**测试用例(呼应 1.2)**:
- G 调、Capo 0 样本 → 应推荐 Capo 0 + 标准调弦
- bB 调样本 → 应推荐 Capo 3 + G 调指法套用
- D 调金属/摇滚 → 应推荐 Drop D 或 Capo 0

**实现位置**:`GuitarProfile.ts` 的 `detectTuning` transform。调性检测若启用,放 `src/core/keyDetector.ts`(与 quantizer 共用音符数据)。

**参考现状**:GitHub 搜索"capo detection guitar"无成熟开源实现,本评分函数为自写、无现成对照。Step 2 实现时以 §1.2 测试集(含 G 调/bB 调/D 调样本)验证推荐正确率,作为唯一验收依据。
